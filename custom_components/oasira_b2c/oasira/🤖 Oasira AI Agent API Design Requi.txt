 🤖 Oasira AI Agent API: Design Requirements Summary

 This document outlines the functional and operational requirements for integrating with the Oasira AI Agent service. The agent is a
 conversational interface that leverages external tools (Home Assistant integration, internal state management) to perform actions
 and retrieve real-time data.

 2. AI Agent Persona & Constraints

 The consuming application must be aware of the strict operational guidelines the agent follows:

 - Role: Intelligent home and senior-living automation assistant.
 - Safety First: The agent strictly enforces safety rules. The consuming application should anticipate potential actions being
   blocked or requiring approval.
 - Approval Flow: Actions categorized as sensitive (unlock, open, high temperature changes) will trigger a needsApproval check within
   the AI flow, requiring explicit confirmation from the user/caller before execution.
 - Language Mandate: The agent is strictly constrained to use unique, fluent, and non-redundant language. The consumer should not
   expect repetitive phrasing.
 - Data Integrity: The agent must not invent sensor or device information.

 4. Direct Status Endpoint (Alternative)

 For applications requiring immediate, non-conversational state checks, a direct API endpoint is available:

 - Endpoint: /api/home/status?homeId=<homeId>
 - Method: GET
 - Purpose: Bypass the full conversational agent flow to retrieve current home status directly.
 - Return: JSON object containing the home status data.

 5. Implementation Notes for Consumers

 1. Error Handling: Implement robust error handling for API calls, especially considering potential network failures or authorization
    issues with the underlying Home Assistant integrations.
 2. State Persistence: If your application relies on conversational continuity, ensure that the necessary context (OasiraState) is
    maintained and correctly passed to the Agent API.
 3. Tool Invocation: The consuming application must be ready to receive structured tool calls from the agent and execute the
    corresponding functions (getHomeStatus, controlDevice, etc.) before returning the results back to the agent for a final response
    generation.
 4. Configuration: The agent relies on external environment variables (HOME_ASSISTANT_URL and HOME_ASSISTANT_TOKEN) for external
    service integration.
